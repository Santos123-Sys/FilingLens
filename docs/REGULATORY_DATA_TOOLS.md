# Regulatory Data Tools Architecture

FilingLens separates probabilistic filing interpretation from deterministic regulatory-data retrieval and Python tooling.

```text
Browser / Dashboard
        |
        v
FilingLens Node API (public)
        |
        +--> filing extraction + classification
        +--> bounded specialist analysis
        |
        +--> private Railway: filinglens-data-tools
                 |
                 +--> SEC EDGAR submissions + CompanyFacts (US)
                 +--> CVM Dados Abertos DFP/ITR (Brazil)
                 +--> exact financial-ratio Python skill
                 +--> exact financial-statement Python skill
                 +--> exact timeline validator
                 +--> python-pptx presentation engine
```

## Source hierarchy

### United States
1. SEC EDGAR structured data (`data.sec.gov`).
2. Uploaded SEC filing bundle.
3. Citation-backed external research when the filing does not support the requested market context.

### Brazil
1. CVM Dados Abertos structured DFP/ITR data.
2. Uploaded CVM filing bundle.
3. Optional CVM convenience provider in the future.
4. Citation-backed external research when required.

Structured data is a cross-check and enrichment layer. It must never silently overwrite a filing-derived fact. Missing identifiers or provider outages degrade to filing-only analysis rather than terminating the pipeline.

## Railway topology

- `FilingLens`: public Node/TypeScript application.
- `filinglens-data-tools`: private Python/FastAPI service.

The main service uses `FINANCIAL_DATA_SERVICE_URL` to reach the private service. The Python service is not intended to have a public domain.

## PowerPoint boundary

PowerPoint is generated by `filinglens-data-tools` with `python-pptx`, not handcrafted browser OOXML. The service saves the package in memory and reopens it with `python-pptx` before returning it. The browser downloads the binary through `/api/presentation`; a generation failure does not discard the completed analysis.

Before rendering, a typed planner adapted from the `ppt-agent` architecture converts the validated
analysis contract into a sequential narrative with action titles, source notes and speaker notes.
After rendering, a deterministic quality gate verifies the package, slide count, planned titles and
the presence of source and data-quality disclosures. See `docs/PPT_AGENT_INTEGRATION.md`.

The presentation rules are defined in `skills/filinglens-powerpoint/SKILL.md`, adapted from the supplied PowerPoint playbook with FilingLens-specific evidence, provenance and financial-storytelling controls.
